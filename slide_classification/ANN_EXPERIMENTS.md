# PAIP-IV ANN Experiments

Four ANN configurations run through PAIP-IV, each repeated four times. This
document records what each experiment configured, how it was run, and what it
produced.

| | Experiment | CSV | Repeats |
|---|---|---|---:|
| **1** | Original (legacy) | `repeats_legacy.csv` | 4 |
| **2** | TCGA-CV hyperparameters | `paip_iv_repeats.csv` | 4 |
| **3** | `ann_old` | `repeats_ann_old.csv` | 4 |
| **4** | `ann_edited` | `repeats_ann_edited.csv` | 4 |

Each CSV holds 88 rows: 22 (aggregation × encoder) combinations × 4 runs, with
every hyperparameter that produced the row.

**All four vary the ANN's configuration.** A fifth line of work — fitting the
decision **threshold** rather than changing the model — is reported separately
under [Threshold calibration](#threshold-calibration). It ran at two inner-CV
fold counts across all five classifier heads, and did not work.

A Word version of this report is generated by `tools/build_ann_report.py`.

---

## Held constant across all four

Nothing below varies between experiments. Only the ANN's configuration and how
it was selected changed.

| | |
|---|---|
| **Cohort** | PAIP, 78 slides |
| **Split** | Provider's own: **47 train** (12 MSI-H) / **31 test** (7 MSI-H) |
| **Protocol** | Single fixed split, no folds, no averaging |
| **Combinations** | 22 — 4 aggregation methods × 5 encoders, plus TITAN and PRISM |
| **Threshold** | 0.5 |
| **Uncertainty** | Percentile bootstrap, 1000 resamples, 95% CI |
| **Seed** | 42 |
| **Optimiser** | Adam, `lr=1e-4`, `weight_decay=1e-4` |
| **LR schedule** | `ReduceLROnPlateau(factor=0.3, patience=5)` |
| **Loss** | `CrossEntropyLoss` on raw logits |
| **Batching** | Full-batch — one Adam step per epoch |
| **Output** | Raw logits; softmax applied only in `predict_proba` |

The 47/31 split is the recovered cohort. Five training slides
(`training_data_19/30/41/42/46`, two MSI-H) previously had no features; their
patches were recovered and features rebuilt, taking the split from 42/31 to the
full 47/31 and train MSI-H from 10 to 12.

## The four configurations

| | **1 · Original** | **2 · TCGA-CV** | **3 · `ann_old`** | **4 · `ann_edited`** |
|---|---|---|---|---|
| Hidden layers | 2 | 2 | **1** | **1** |
| `hidden_dim1` | searched | **from TCGA-CV** | 512 | 512 |
| `hidden_dim2` | searched | from TCGA-CV | — | — |
| `max_iter` | searched → 500 | from TCGA-CV → 500 | **1000** | **1000** |
| Dropout | 0.3 | 0.3 | **0.5** | **0.7** |
| Early-stop patience | 20 | 20 | 10 | 10 |
| **Grid points evaluated** | **18** | **1** | 1 | 1 |
| **Selected on** | 9 PAIP slides | *nothing — pinned* | *nothing — pinned* | *nothing — pinned* |
| **ANN trains on** | **38 of 47** | **47** | **47** | **47** |
| Slides held back | 9 | 9 (early stop) | **0** | **0** |
| Hyperparameters from | PAIP search | TCGA-CV folds | collaborator script | collaborator script |
| Runner flag | *(default)* | `--ann-protocol fixed` | `--ann-protocol full --ann-preset ann_old` | `--ann-protocol full --ann-preset ann_edited` |

### 1 · Original (legacy)

The pipeline as originally written. The ANN searches an 18-point grid
(`h1{128,256,512} × h2{64,128,256} × iter{500,1000}`) and selects on macro-F1
computed over a stratified 20% carve-out — **9 slides**, roughly 7 non-MSI-H and
2 MSI-H. The carve-out is *not* returned for the final fit, so the ANN trains on
38 slides.

Two properties of this design are worth stating, because they motivated the
other three experiments:

- **`lin`, `knn`, `proto` and `rf` all merge the carve-out back** and train on
  all 47 (`logistic.py:19`, `knn.py:33`, `protonet.py:40`,
  `r_forest_eval.py:240`). The ANN is the only head in the comparison training on
  less data.
- **The selection is not informative at that size.** Across the 22 combinations
  the 18 configurations collapse to a median of 3 distinct validation scores. The
  configuration chosen averages **0.6075** test macro-F1 against **0.6133** for
  the grid's median entry — worse than picking at random from its own grid. The
  grid's best entry averages 0.6623, so 0.055 is the headroom being lost.

### 2 · TCGA-CV hyperparameters

Removes both problems. The configuration is taken from the majority vote across
the four TCGA-CV folds — each validating on ~100 slides rather than 9 — and the
model is refit on all 47. TCGA is a separate cohort, so no PAIP information
enters the choice.

Eight distinct configurations across the 22 combinations; `max_iter = 500` in
every one.

### 3 & 4 · The collaborator's scripts

`ann_old.py` and `ann_edited.py` implemented as presets, taken verbatim: one
hidden layer of 512, 1000 iterations, patience 10. **Dropout is the only
hyperparameter the two scripts differ on** — 0.5 versus 0.7. TCGA-CV is not
consulted at all, so every value traces to the collaborator's file.

> **Not reproduced:** `ann_old.py` places `nn.Softmax` inside the training graph
> while using `CrossEntropyLoss`, which applies log-softmax again. Softmax twice
> flattens gradients and underfits. That is a defect rather than a
> hyperparameter, so the preset carries its dropout of 0.5 but emits raw logits
> like everything else.

## Reading the results

**Every configuration beats the original.** Mean balanced accuracy rises from
0.6921 to 0.7166–0.7321 in all three alternatives. The original is last on that
measure.

**The two metrics disagree about which alternative wins.**

| | mean BalAcc | mean AUROC |
|---|---:|---:|
| TCGA-CV | 0.7166 | **0.8249** |
| `ann_edited` | 0.7255 | 0.8190 |
| `ann_old` | **0.7321** | 0.8106 |

Balanced accuracy and AUROC move in *opposite* directions across these three.
AUROC is threshold-free, so a rising BalAcc with a falling AUROC means the
single-layer variants sit at a better operating point while ranking slides
slightly worse. **On AUROC — the stated primary metric — the TCGA-CV
configuration is the strongest, and it also produces the single best row
(0.8244 / 0.9048).**

**One test slide is worth 0.071 balanced accuracy.** With 7 positive slides,
flipping one moves BalAcc by 1/14. The entire spread between the three
alternatives (0.7166 → 0.7321, i.e. 0.0155) is **under a quarter of one slide**.
Differences at that scale should not be used to rank them; the gap from the
original (0.024–0.040) is larger but still deserves the bootstrap intervals
rather than a point comparison.

**Experiments 3 and 4 change three things at once** versus experiment 2 — depth
(2→1), dropout (0.3→0.5 or 0.7), and iterations (500→1000). Any difference
between them and experiment 2 cannot be attributed to one of those alone.
Between 3 and 4 the comparison *is* clean: dropout is the only difference, and
0.5 gives +0.0066 mean BalAcc but −0.0084 mean AUROC against 0.7.

**Provenance differs, and it matters independently of the score.**

| Experiment | Where the hyperparameters came from |
|---|---|
| 1 · Original | selected on 9 PAIP training slides |
| 2 · TCGA-CV | majority vote across 4 TCGA-CV folds — a separate cohort |
| 3 · `ann_old` | the collaborator's script |
| 4 · `ann_edited` | the collaborator's script |

Experiments 2–4 can all state that nothing was tuned on PAIP. Experiment 1
cannot.

## Threshold calibration

A different kind of experiment: it changes the **decision rule**, not the model.
A threshold is fitted by stratified inner cross-validation over the 47 training
slides, pooled out-of-fold, then applied to the 31 test slides — which take no
part in fitting it. It runs for **all five classifier heads**, not the ANN alone;
calibrating one head and not its competitors would replace one unfair comparison
with a different one.

0.5 remains the reported operating point throughout. The fitted figures live in
`threshold_audit.csv` and in three extra `summary_iv.csv` columns (`TauTrain`,
`BalAcc_at_TauTrain`, `ConfMatrix_at_TauTrain`) alongside the headline, never
instead of it. **Nothing in the sections above changes** — threshold work does
not alter the models.

Run at two fold counts, 22 combinations each, all five heads.

### Result — it does not work, at either fold count

Means over the 20 aggregation rows per head:

| Head | BalAcc @ 0.5 | @ tau (5-fold) | Δ | @ tau (4-fold) | Δ |
|---|---:|---:|---:|---:|---:|
| lin | 0.7710 | 0.7112 | **−0.0598** | 0.7365 | −0.0345 |
| proto | 0.7506 | 0.6894 | **−0.0612** | 0.6936 | **−0.0570** |
| knn | 0.7634 | 0.7351 | −0.0283 | 0.7442 | −0.0192 |
| rf | 0.7259 | 0.6935 | −0.0324 | 0.7094 | −0.0165 |
| **ann** | 0.7146 | 0.7085 | −0.0061 | **0.7241** | **+0.0095** |

**Four of five heads lose at both fold counts.** The ANN is the only head that
gains, and only at 4 folds, by +0.0095 — an eighth of one test slide. At
tau_train it still ranks **third**, behind `knn` and `lin`.

Across all 110 rows of the 4-fold run: **63 worse, 31 better, 16 unchanged.**

AUROC is unaffected, being threshold-free.

### The fitted thresholds are not stable

| Head | tau range (4-fold) | median | median (5-fold) |
|---|---|---:|---:|
| lin | 0.003 – 0.630 | 0.040 | **0.018** |
| knn | 0.200 – 0.667 | 0.367 | 0.400 |
| proto | 0.476 – 0.500 | 0.494 | 0.492 |
| rf | 0.176 – 0.343 | 0.270 | 0.238 |
| ann | 0.116 – 0.987 | 0.427 | 0.361 |

`lin` fits thresholds as low as **0.003** and its median moves 3× between fold
counts. The ANN's range spans almost the entire unit interval. A threshold fitted
from 12 positives is dominated by noise, not by any property of the model.

Fewer folds was *less* harmful for every head — the opposite of what the
train-size argument predicts (inner models see 35 slides at k=4 against 38 at
k=5, both below the final model's 47). That the direction reverses under a change
this small is itself evidence the estimate is unstable.

### What it does not do

A per-row check corrects an intuition worth recording. Because balanced accuracy
weights the 24 negatives and 7 positives equally, a threshold that trades
sensitivity for specificity can raise the metric while detecting fewer cancers.
That is **not** what happens here:

| False negatives at tau_train vs 0.5 | rows |
|---|---:|
| More missed positives | 3 |
| Fewer missed positives | 32 |
| Unchanged | 75 |

Of the 31 rows where balanced accuracy improved, only **one** did so while
missing more positives. tau_train generally makes models *more* sensitive, not
less. The procedure fails on accuracy, not on safety.

### Conclusion

Recorded as a negative finding, now resting on two independent fold counts rather
than one: *a decision threshold fitted by inner cross-validation on 47 training
slides does not transfer to the model trained on all 47. It degrades four of five
classifier heads at both k=4 and k=5, and the fitted values are unstable enough
that the fold count changes them severalfold.*

The ANN's deficit is in **ranking**, not operating point — its median AUROC is
0.8244 against kNN's 0.8557 — and no threshold can close that.

```bash
python runners/iv_runner.py --ann-protocol fixed --fit-threshold --force
python runners/iv_runner.py --ann-protocol fixed --fit-threshold --tau-folds 4 --force
```

## Reproducing

From `slide_classification/`, in the project environment:

```bash
# 1 · Original (legacy) - runner defaults
python run_iv_repeats.py --classifiers ann --out repeats_legacy.csv

# 2 · TCGA-CV hyperparameters, refit on all 47
python run_iv_repeats.py --ann-protocol fixed --classifiers ann \
    --out paip_iv_repeats.csv

# 3 · collaborator's ann_old
python run_iv_repeats.py --ann-protocol full --ann-preset ann_old \
    --classifiers ann --out repeats_ann_old.csv

# 4 · collaborator's ann_edited
python run_iv_repeats.py --ann-protocol full --ann-preset ann_edited \
    --classifiers ann --out repeats_ann_edited.csv

# 5 · threshold fitted on the training slides, all five heads (single run)
python runners/iv_runner.py --ann-protocol fixed --fit-threshold --force
```

`run_iv_repeats.py` runs `iv_runner.py --force` four times, harvests each run's
results plus its full hyperparameter record into the CSV, deletes the
intermediate trees, and leaves the final run as the live `PAIP_IV_Results/`.
Flags it does not recognise are forwarded verbatim to the runner.

Each sweep archives the previous `PAIP_IV_Results/` rather than deleting it.
Because each sweep leaves its own run live, **regenerate the reports immediately
after whichever experiment you intend to publish**:

```bash
cd ..
python tools/write_results_md.py
python tools/build_supplementary_results.py
```

### Why four repeats

The pipeline seeds `torch` and `numpy` before every fit and draws the carve-out
with a seeded stratified split, so repeats at a fixed configuration are expected
to be identical. All four runs of all four experiments were **bit-identical**
across balanced accuracy, both CI bounds, AUROC, both CI bounds, accuracy,
macro-F1, threshold and confusion matrix.

That is a reproducibility check, not a variance estimate: it establishes that
every figure above is exact rather than one draw from a distribution, and rules
out GPU nondeterminism — which is not guaranteed for BatchNorm and which the
pipeline does not explicitly configure away. It says nothing about how much a
result would move under a different random draw; that would require varying the
seed, which changes the carve-out composition as well as the initialisation.

## CSV schema

Columns fall into three groups.

| Group | Columns | Written by |
|---|---|---|
| Identity | `run`, `Experiment`, `Method`, `Model`, `Classifier` | runner |
| Results | `BalAcc`, `BalAcc_CI_low/high`, `AUROC`, `AUROC_CI_low/high`, `Acc`, `MacroF1`, `Threshold`, `ConfMatrix`, `N_train`, `N_test`, `N_train_effective`, `AnnProtocol` | runner |
| Configuration | `hp_*` | harvesting script |

`N_train_effective` is authoritative for how many slides the classifier fitted
on. The `hp_*` columns are read from the run's own checkpoint config and result
stamp where available, and from the source otherwise; anything that cannot be
determined is recorded as `?` rather than guessed.

`hp_grid_size` reports the source grid's size (18) rather than the number of
points actually evaluated when a configuration is pinned. Use `hp_selected_on`
to tell them apart: it is `val_ann_macro_f1` when a search ran and empty when
the configuration was pinned.
